# Disclosure Review

Complete this review before publishing any case study, diagram, screenshot, dataset, metric, demonstration, or supporting artifact.

## Provenance and Ownership

- [ ] The artifact was created independently or is explicitly authorized for publication.
- [ ] No employer or client artifact was copied, sanitized, traced, redacted, renamed, or closely reconstructed.
- [ ] Personal contribution and team contribution are distinguished accurately.
- [ ] Publication rights for coursework, third-party material, and externally generated assets are confirmed.

## Professional and Confidential Information

- [ ] Employer and client intellectual property is excluded.
- [ ] Internal terminology, project names, product names, and recognizable workflow details are excluded.
- [ ] Real customer, employee, account, incident, or investigation information is excluded.
- [ ] Internal URLs, private hostnames, repository names, resource identifiers, and network details are excluded.
- [ ] The artifact cannot be combined with other portfolio pages to fingerprint a sensitive architecture.

## Credentials and Metadata

- [ ] Credentials, secrets, tokens, keys, cookies, session data, and account identifiers are absent.
- [ ] Screenshots contain no sensitive tabs, notifications, filenames, paths, timestamps, background content, or browser data.
- [ ] Image, document, and export metadata has been inspected and removed where necessary.
- [ ] Generated examples use fictional identities, organizations, infrastructure, and data.

## Protected Implementation

- [ ] Exact detection rules, production queries, thresholds, weights, and scoring formulas are excluded.
- [ ] Proprietary feature calculations, sensitive attack paths, and unremediated weaknesses are excluded.
- [ ] Trading strategies, signals, indicators, formulas, thresholds, balances, history, and account data are excluded.
- [ ] Private AI prompts, agent instructions, model configurations, routing logic, and confidential evaluation data are excluded.
- [ ] Source code and configuration are included only when ownership and disclosure have been explicitly approved.

## Claims and Evidence

- [ ] Implemented, designed, experimental, and conceptual work are labeled correctly.
- [ ] Professional, independent, and mixed ownership are labeled correctly.
- [ ] Architecture diagrams are conceptual or independently created and do not imply an undisclosed production topology.
- [ ] Metrics are current, dated, scoped, reproducible where appropriate, and supported by a stated method.
- [ ] Qualitative outcomes are substantiated and do not imply unsupported scale or impact.
- [ ] Planned evidence is not presented as existing evidence.
- [ ] Limitations and unverified areas are visible.

## Repository and History

- [ ] All staged and tracked files have been reviewed, including filenames and binary assets.
- [ ] Sensitive-pattern and secret scans have been run against the working tree.
- [ ] Relevant Git history has been inspected; deleting a file from the current tree is not treated as removing it from history.
- [ ] Private material was never committed temporarily for later sanitization.
- [ ] Links point only to intended public content.

## Decision

- [ ] **Publish** — safe and substantiated within the stated scope.
- [ ] **Revise** — specific disclosure or claim issues must be corrected.
- [ ] **Keep Private** — publication risk or ownership cannot be resolved safely.
